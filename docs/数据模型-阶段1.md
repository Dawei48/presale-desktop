# 放心预 · 数据模型（阶段1 · 最终极简版）

> 核心目的：把「预售」订单挑出来，导出成窑口生产单表格。
> 判定规则：**靠备注关键词**，无商品属性、无复杂状态机、无库存。

---

## 一、订单分类（唯一判定：备注关键词）

| 类型 | 值 | 判定 | 干什么 |
|---|---|---|---|
| 预存 | `stored` | 备注含「预存」 | 挂账，不导出 |
| 预售 | `presale` | 备注含「预售」 | **导出给窑口** |
| 现货 | `normal` | 都不含（默认） | 简单记录，可标已发货 |

优先级：备注同时含「预售」和「预存」时，按「预存」处理（更强的挂起信号）。

识别方式：**规则匹配为主**（备注含关键词即判），**AI 兜底**（备注写得不规范、含"现做""先存着"等模糊表达时用 AI 判断）。

---

## 二、发货状态（极简）

每个订单一个「发货」标记，用于避免重复导出：

| 值 | 含义 |
|---|---|
| `unsent` | 未发货（默认） |
| `sent` | 已发货 |

导出生产单 = 预售订单 + 未发货。发货后标记 `sent`，不再导出。

---

## 三、表结构

### products 商品
```
id, brand_id, name, image_path, notes, created_at, updated_at
```

### product_skus 商品规格（陶瓷：釉色/尺寸）
```
id, product_id, spec(规格名，如"青花·大号"), price, created_at
```

### orders 订单主表
```
id
order_no        订单号
shop_type       平台（douyin/taobao/pdd/kuaishou/shipinhao）
order_type      normal / presale / stored（靠备注关键词）
ship_status     unsent / sent
customer        客户名
receiver_name   收货人
receiver_phone  收货电话
receiver_addr   收货地址
amount          实付金额
notes           备注（判定订单类型的关键）
deadline        交期（可选，窑口确认时间）
created_at      下单时间
updated_at
```

### order_items 订单明细（一单多品）
```
id
order_id
sku_id          （可空）
goods_name      商品名（CSV 原始名，兜底）
spec            规格文本
quantity        数量
price           单价
```

---

## 四、导出生产单（核心）

```
导出 = order_type='presale' 且 ship_status='unsent'
按 SKU/商品合并 → 表格列：产品图 | 产品名 | 规格 | 数量 | 备注 | 交期
```

排除：预存（stored）、现货（normal）、已发货（sent）。

---

## 五、CSV 导入要识别的字段

| 字段 | 现状 | 现在 |
|---|---|---|
| 订单号 | ✅ | 保留 |
| 客户名 | ✅ | 保留 |
| **商品名** | ❌ 丢了 | ✅ 正确关联商品/SKU |
| **收货人/电话/地址** | ❌ 丢了 | ✅ 存下来 |
| **金额** | ❌ 丢了 | ✅ 存下来 |
| 数量 | ✅ | 保留 |
| 备注 | ✅ | 保留（含「预存」→stored，含「预售」→presale）|
| 下单时间 | ✅ | 保留 |

---

## 六、明确不做

- ❌ 商品级现货/预售属性
- ❌ 「待确认延发」状态
- ❌ 库存、烧坏返工、生产进度跟踪
- ❌ 电子面单打印、售后模块
