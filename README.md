# 放心预 · 陶瓷预售协同

面向景德镇陶瓷直播电商的**预售生产协同工具**。核心就一件事：把直播间卖出去的「预售单」整理成一张能给窑口照着做的生产单。

> 陶瓷不是「下单即有货」——卖了才去窑口定做，交期按月算。通用电商 ERP 的「下单→打单发货」逻辑在这里是断的，中间缺了最要命的「生产」环节。

## 它解决什么

直播卖陶瓷，一场几百单，实际是三种完全不同的单子混在一起：

| 类型 | 判断依据 | 处理方式 |
|---|---|---|
| **现货** | 备注里没关键词（多数） | 48 小时内打单发货 |
| **预售** | 备注含「预售」 | 先在平台发延后发货申请 → 客户同意 → 报窑口做 20–30 天 → 拿货发货 |
| **预存** | 备注含「预存」 | 消费券挂账，不发货也不生产 |

人工做法是导出订单 Excel，筛出预售的，按窑口凑成一张表发过去——一单错就整批错。这工具把这步自动化了。

## 功能

**订单**
- CSV 导入（淘宝 / 拼多多 / 抖音 / 视频号），多编码兼容（UTF-8 / GBK / GB2312）
- **规则 + AI 双识别列名**：常见列名规则直接认（快、免费），冷门说法（「给客服的话」「收件地」）交给 DeepSeek 语义识别
- 按订单号查重，重复导入自动跳过，不覆盖手工改过的状态
- **备注自动分类**：写「预售」→ 类型转预售、状态进「待确认延发」；写「预存」→ 直接挂账
- 手动新增 / 编辑 / 删除订单，行内一键推进状态
- 状态机：待确认延发 → 待生产 → 待发货 → 已发货 → 已完成（+ 预存挂账）

**生产单**
- 按**窑口**聚合（窑口取商品名第一段：「玉柏 · 青花缠枝莲 · 盖碗」→ 玉柏）
- 每个窑口一张单，同款同规格自动合并数量
- 导出 Word：印章 logo + 带框表格 + 斑马纹，列 = 产品图片 / 产品名称 / 数量 / 价格 / 备注

**商品库**
- **找图**：按商品名搜网图，给 9 张候选让人选，选中才入库（搜图会错配，不自动替换）
- **上传**：本地选图，压缩后入库

**其他**
- 深色 / 浅色 / 跟随系统三套主题，切换同步 Windows 标题栏
- 全局搜索（Ctrl+K）
- 数据全本地，每天启动自动备份，保留 7 天

## 下载

前往 [Releases](https://github.com/Dawei48/presale-desktop/releases) 下载最新的 `presale-desktop.exe`。

双击运行，不需要装 Python。

## 使用流程

1. 打开软件 → 点「导入订单」选各平台导出的 CSV
2. 导入后自动分类：现货进待发货，预售进待确认延发，预存挂账
3. 「待确认延发」的单：平台发延后申请 → 客户同意 → 点「标记已同意」
4. 切到「窑口」页 → 点某窑口的「导出生产单」→ Word 发给窑口
5. 窑口做完拿货 → 回「全部订单」点「去发货」→ 填单号发走

## 数据存在哪

**全部在本机**，不联网：

```
你的文件夹/
├── presale-desktop.exe
└── data/
    ├── presale.db          ← 所有订单、商品
    ├── images/             ← 产品图
    ├── backup/             ← 每天自动备份，保留 7 天
    ├── settings.json       ← 主题等设置
    └── ai_key.txt          ← （可选）DeepSeek key，用了 AI 识别才需要
```

⚠️ **换新版时把整个文件夹拷过去，别只拷 exe**，否则数据会丢。

## AI 识别（可选）

不配 key 也能用，只是冷门列名认不出来，需要手工映射。

配置方式：在 `data/ai_key.txt` 里写一行 DeepSeek API Key 就行。

## 技术栈

| | |
|---|---|
| 界面 | pywebview + Edge WebView2（HTML/CSS/JS，无框架） |
| 后端 | Python + SQLite |
| 导出 | python-docx（自定义表格 XML） |
| 打包 | PyInstaller onefile |

早期版本用 CustomTkinter，界面卡顿且做不出透明质感——Tk 在 Windows 没有 GPU 加速，每个圆角卡片都是一次 Canvas 重绘。换成 WebView2 后滚动和动画都是 GPU 合成。

## 开发

```bash
pip install -r requirements.txt
python main_web.py              # 直接跑
python audit.py                 # 71 项静态/API/导出/打包自审
python selfcheck.py             # 业务逻辑自审
python tests/e2e_bridge.py      # 端到端：真开窗口、真点按钮、回库核对
```

`tests/e2e_bridge.py` 是最重要的一关。它会真的打开窗口点「标记已同意」，
然后回数据库确认状态真的变了——因为「界面看起来正常」和「数据是真的」
完全是两回事，v2.0.1 之前就栽在这上面（见版本记录）。

用浏览器直接打开 `web/index.html` 会进**预览模式**（假数据），方便调样式，不会碰真实数据库。
